Separate methodology guide

How X footprint replication works.

This strategy first makes a geographically balanced copy of X’s site pattern. Only then does it subtract locations already represented by B.

70% of sites is not 70% coverage. Coordinates do not contain RF range, antenna configuration, terrain, clutter, traffic, population, or capacity. The retention percentage controls site count only.

The idea in four actions

1

Measure X spacing

Find how close or far apart X sites normally sit.

2

Allocate local quotas

Give each occupied geographic zone its share of the percentage target.

3

Spread the choices

Inside each zone, choose X sites that are separated rather than bunched.

4

Subtract B overlap

Remove selected X sites with a B site inside the overlap distance, then refill locally if enabled.

1. Preserve local X density

The app chooses a zone width from typical X-to-X spacing. The default width is four times that spacing, so the grid adapts to the scale of X’s deployment.

2. Spread choices inside each zone

Why this matters

Taking the first 70% of CSV rows would be arbitrary. Random sampling could also create holes. Spread-first selection gives the retained set a more even geographic shape while still respecting each zone’s quota.

The result is deterministic: the same files and settings produce the same site set. Very large zones use a faster deterministic spatial ordering, explained in the audit rules below.

3. Remove B overlap and refill locally

Adaptive overlap

overlap distance = overlap ratio × local B spacing

With the default ratio 0.40, a locality where B sites are normally 2 km apart uses about 0.8 km as its overlap distance.

Fixed overlap

Use a fixed kilometre value only when engineering or commercial policy defines one distance everywhere.

Exact implemented behaviour

Calculation and audit rules

The diagrams above explain the concept. The rules below describe exactly how the current engine produces a reproducible result.

1. Input validation

  • Column names are matched without regard to capitalization or surrounding spaces. Each CSV must contain siteid, latitude, and longitude.
  • Missing site IDs, non-numeric coordinates, out-of-range coordinates, duplicate site IDs, and duplicate coordinates are excluded. Duplicate IDs are compared without regard to capitalization; the first valid occurrence is kept.
  • Every excluded row is written to the replication data-issues CSV. If either operator has no valid sites, the run stops.

2. Distance and density calculations

local X spacing = median great-circle distance to the configured nearest other X sites
  • Neighbour and B-overlap distances use WGS84 latitude/longitude on a spherical Earth.
  • Typical X spacing for the whole dataset is the median nearest-X-neighbour distance across all valid X sites.
  • Each B site first receives its own nearest-B-neighbour spacing. For an X candidate, local B spacing is the median of those spacing values among the configured nearest B sites.
  • If only one site exists for an operator, the engine uses a safe fallback spacing so the run remains calculable.

3. Overall target and local quota reconciliation

overall target = max(1, floor(valid X sites × retention percentage ÷ 100 + 0.5))
  • The target is capped at the valid X-site count. Adding 0.5 before taking the floor implements ordinary whole-number rounding.
  • Every zone starts with a raw quota of zone X count × retention percentage. The engine initially takes the whole-number floor.
  • The minimum-per-zone rule is enforced only when the overall target is large enough to give that minimum to every occupied zone.
  • Remaining sites are distributed by largest fractional remainder, then larger zone size, then stable zone ID. If minimum quotas create an excess, the reverse reconciliation removes the excess. Final zone quotas always add to the overall target.
  • Therefore, a three-site zone at 70% can receive two or three sites depending on how all zone remainders reconcile to the exact overall target.

4. Zone geometry and boundary effects

zone width = max(typical X spacing × zone scale, 0.05 km)
  • Latitude and longitude are converted to local east/north kilometre coordinates around the dataset’s median location. Square grid cells are then anchored from the westernmost and southernmost X coordinates.
  • The grid is a calculation device, not an administrative or RF boundary. Two nearby sites on opposite grid edges can belong to different zones.
  • No circle, state, district, licensed-service-area, or custom polygon boundary is applied. A distant X outlier may form its own occupied zone and can receive the configured minimum representation.

5. Within-zone spread order

  • For a normal-sized zone, the first candidate has the largest local X spacing. Each next candidate maximizes its shortest projected distance to candidates already chosen.
  • Distance ties prefer the candidate with larger local X spacing; any remaining tie is resolved by site ID. This makes repeated runs deterministic.
  • For a zone containing 548 or more sites, the engine uses a deterministic coordinate-based spatial ordering instead of the full farthest-point loop to protect performance. It remains reproducible but is not guaranteed to maximize separation at every step.
  • Great-circle geometry is used for network neighbour and overlap distances. The square zones and within-zone spread order use the local planar east/north projection.

6. B-overlap decision and local refill

adaptive threshold = overlap ratio × local B spacing
  • Fixed mode uses the entered kilometre value for every X site. Adaptive mode calculates a different threshold for each locality.
  • An X site passes when its nearest-B distance is greater than or equal to its overlap threshold. A site strictly inside the threshold is rejected.
  • The initial zone quota is tested first. When refill is enabled, rejected sites are replaced using the next sites in that same zone’s spread order.
  • A backup that also overlaps B is marked red and the engine continues to the next same-zone backup. It never borrows a replacement from another zone.
  • If the zone runs out of non-overlapping backups, the final portfolio remains below the requested target. This is intentional and visible in the result-count flow.

7. Statuses, counts, and ordering

Selected X footprint
An initial representative site or same-zone refill that passed B overlap.
B overlap removed
Any initial or backup candidate actually tested and rejected for B overlap.
X not retained
A valid X site not needed by its zone quota and not tested as an overlapping backup.
Final order
An audit/display sequence sorted by zone ID, within-zone pick order, and site ID. It is not a commercial-benefit ranking.

Because failed backup candidates are also red, the red map-layer count can be larger than the “Initial B overlaps” KPI. The complete all-sites CSV records the zone, quota, pick order, nearest B, overlap threshold, status, and reason for every valid X site.

How to evaluate the output

  1. Compare the final selected count with the representative target.
  2. Use the map layer counts to confirm gold sites remain across X’s occupied geography.
  3. Inspect red overlap removals, particularly in places where B density is high and X density is low.
  4. If known strategic X sites are removed, do not solve that only by lowering the overlap rule; add RF, terrain, traffic, or strategic-site evidence.
  5. Compare this result with the original B gap-filling workflow. The two lists answer different questions and should not be expected to match.
